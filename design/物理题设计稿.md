## 1. 领域选择：功率模组一维多层散热瞬态仿真（热传导 PDE · FTCS 有限差分）

选择依据（对照"数值判据可验性"标准，三重探针全部可落地）：

| 判据类型 | 物理载体 | 验题落地方式 |
|---|---|---|
| 解析极限 | 多层平壁串联热阻稳态（分段线性温度场） | 界面通量连续 + 解析温降对照，容差 1% |
| 收敛阶 | 二阶中心差分网格加密误差比 ≈ 4 | Δx 与 Δx/2 误差比 ∈ [2.5, 5.5]，抓离散化阶数错 |
| 稳定性定理 | FTCS 显式格式 dt ≤ Δx²/(2α) | 探针网格 + dt=0.9×真实极限，naive 降 10×/100× 仍发散（构造性） |
| 时标尺度 | 热扩散时间 τ ∝ L²/α | 阶跃响应时标 ±10%，抓单位/固化错误 |
| 守恒量 | 全局能量平衡（流入−流出 = 储能速率） | 残差 < 0.5%，抓源项/通量符号类错误 |

其他候选领域落选理由：轨道力学（Verlet 能量漂移判据好，但边界条件类 bug 无自然载体）；
振动/波动（bug 链的自然分层不如多层介质丰富——多层材料天然给出"数据层→换算层→校准层→
求解器"的链路结构，与 431 题多层组件链同构）。

## 2. 场景与叙事

**业务背景**：功率模组（芯片→TIM 热界面材料→铜基板→液冷）一维瞬态热仿真工具链，
用于评估"下一代芯片功率密度提升 1.5×"后结温是否逼近 110 °C 节流阈值——即热预算
sizing 要为功率继续增长预留余量（对齐 431 题"Trace 上下文随跳数增长预留余量"主题）。

**故障叙事**（对齐 431 题"多次入口重构、对齐从未端到端核验"）：这套工具链近期经历了
三次变更——① v2 材料库目录重组；② 网格加密一倍（v2 网格）；③ 校准流程更替
（引入"实测拟合校准优先"）。变更后评审打回仿真报告：瞬态响应迟钝约三个量级、界面温降
与实测不符、网格无关性检验不过、细化工序上线后仿真直接跑挂（NaN）。多个模块共同作用，
不是"某个参数写错"这么简单。

## 3. 故障链总表（核心设计）

### 3.1 物理故障（模式 A 主体，5 项）

| 编号 | 类别(难度) | 位置 | 故障内容 | 表层症状 | 抓捕探针 | 修复方式（允许多解） |
|---|---|---|---|---|---|---|
| F1 | 单位混乱(中) | `thermo/materials.py` 加载器 | 材料库 CSV 为 SI 口径（cp: J/(kg·K)），加载器沿用遗留 kJ 口径把 cp 再 ×1000 → α_used = α/1000 | 瞬态响应迟钝 ~3 个量级；且错误的小 α 掩盖了 F4 超限 | P7 时标 + P6 联动 | 修正换算方向 / 去换算 |
| F2 | 边界条件错(高) | `thermo/solver.py` 冷却面节点方程 | config 声明对流边界 Robin（h, T_inf），实现写成 Dirichlet T=T_inf，h 未参与 | 扫 h 完全无响应；稳态冷却面温度错 | P3 h/T_inf 扫描 | 改 Robin 通量式（ghost 或通量形式均可） |
| F3 | 离散化错误(高) | `thermo/solver.py` 材料界面通量 | 界面导热系数用算术平均 (k1+k2)/2，应为串联热阻调和平均 2k1k2/(k1+k2) | 界面温降与串联热阻解析解不符；网格加密不收敛（误差平台） | P4 界面物理 + P5 收敛阶 | 调和平均 / 界面通量匹配格式 |
| F4 | 算法参数错(高) | `config.yaml` time.dt=5e-3 s | v1 粗网格验证值沿用至 v2 细网格，超 FTCS 稳定极限（TIM 层临界 ~4.0e-5 s，超限 ~124×） | NaN/温度爆表；**且在 F1 修复后才显形**（错误小 α 下 Courant 数看似安全） | P6 稳定性探针 | 算极限并落配置 / 内部子步自适应（结果须对） |
| F5 | 项缺失(高·可裁剪) | `thermo/solver.py` | 材料库有 `r_contact`（界面接触热阻）列，求解器未实现该列 | 带 R_c 探针场景界面 ΔT 偏小 | P4 的 R_c 场景 | 界面附加热降 q·R_c |

### 3.2 环境陷阱（模式 C 叠加，4 项）

| 编号 | 类别 | 位置 | 机制 | 表层症状 | 抓捕探针 |
|---|---|---|---|---|---|
| E1 | 依赖缺失 | `thermo/qc_crosscheck.py` import scipy | 镜像重建后 requirements 未重放，scipy 缺失；离线 wheelhouse 在 /opt/wheelhouse（含 scipy 轮子，无网络） | qc 阶段 ImportError 崩溃（**链路首个表象**） | P0 + P1 |
| E2 | 配置指向错误路径 | `config.yaml` material_db | 指向重组前路径 `data/materials_v2.csv`，实际在 `data/materials/v2/materials.csv`；loader **静默回退**内嵌默认合金参数（WARN 仅进 stderr 日志） | 材料参数为"默认合金"而非库值 | P9 日志行为检查 + P2 |
| E3 | 固化校准陷阱 | `data/calibration/fitted_2023.npz` | loader 实现"实测拟合优先"逻辑：校准文件存在则固化 α 直接覆盖材料库——固化值带着 F1 同源错误的换算（Python 版 go:embed 编译期固化，改盘不生效） | 修好 F1 后瞬态仍错；改材料库不生效 | P8 行为检查（改名后输出必须不变）+ 数值扫描辅助 |
| E4 | 诱饵 | `config.prod.yaml` + 环境变量 | prod 配置数值**全对但入口只读 config.yaml**（复刻 quota.prod.yaml）；`THERMO_UNIT_SYSTEM=si` 导出但代码从未读取（复刻 HEADER_LIMIT_PROFILE） | 改错文件以为修好 | P1 无变化 + 报告归因 |

### 3.3 故障链因果序（六层，复刻并超过 431 题四层链）

```
E1 qc阶段ImportError崩溃（第一表象）
 → E2 材料库静默回退默认值（表象消失但参数错）
  → F1/E3 固化校准+换算×1000 → 瞬态迟钝3个量级（表象：迟钝）
   → F4 修正单位后 α 变大 → dt 超稳定极限 → NaN 跑挂（表象：修好反而挂）
    → F3 界面算术平均 → 网格无关性不过（表象：加密不收敛）
     → F2 冷却面 h 无响应（表象：扫参数不动）
      → 预警观测 / 热预算余量产物（防线层）
```

关键设计点（继承 431 题"陈旧部署/编译期固化"的被验证手法）：
- **F1×E3 同源双载体**：换算错误既在加载器（可改）又在固化 npz（数据固化，改加载器不生效）
  ——与 431 题配额"磁盘配置 + go:embed 编译固化"完全同构；
- **F1×F4 掩蔽耦合**：错误的小 α 使超限的 dt 看似安全 → 修好单位后发散才显形，
  复刻"修好一层才暴露下一层"的链式排障体验；
- **F4 惩罚拍脑袋**：naive 把 dt 降 10×/100× 仍超极限（5e-3 → 5e-5 > 4.0e-5），
  必须真正推导 FTCS 极限（或实现自适应子步）才能通过 P6。

### 3.4 grep 可解性自检（对齐一轮质检 2.2）

每个故障的**修复**都需要领域判断，非 grep 替换可解：
- F1：需对照 CSV 表头单位口径判断换算方向；
- F2：需理解第三类（对流/Robin）边界与第一类的语义差；
- F3：需理解串联热阻 → 调和平均（算术平均对 TIM/Cu 界面通量偏差 ~96%，量级常识判断）；
- F4：需推导 Δx²/(2α) 并对多层取 min（TIM 层 Δx 最细、α 最小，是控制层）；
- F5：需对齐数据 schema 与求解器实现；
- E3：需读懂 loader 优先级逻辑；E1：需环境诊断 + 离线 pip；E2：需从日志三角定位静默回退。

## 4. 环境架构（构建阶段蓝图）

```
/app/thermo/
  config.yaml                    # 主配置（含 E2 错路径、F4 dt=5e-3、冷却面 Robin 声明）
  config.prod.yaml               # E4 诱饵（数值全对，从未被读）
  run_pipeline.py                # CLI 入口：--config/--out-dir/--stage/--warnings-file
  requirements.txt               # numpy==x, scipy==y（E1：镜像内只装了 numpy）
  thermo/
    paths.py materials.py        # E2 路径回退；F1 换算；E3 校准优先级
    solver.py                    # F2 边界 / F3 界面 / F4 读 dt / F5 未实现 R_c
    postprocess.py               # 稳态判据、峰值温度、t_threshold、能量平衡、告警（纯 numpy）
    qc_crosscheck.py             # 半解析参照交叉验证（import scipy → E1 崩点）
    report.py                    # summary JSON 产出
  data/
    materials/v2/materials.csv   # 真实材料库（SI，含 r_contact 列）
    materials_v2.csv             # 不存在（E2 指向）
    calibration/fitted_2023.npz  # E3 固化校准（含 ×1000 错误的固化 α）+ meta.json（口径自述）
  legacy/solver_v1.py            # 退役求解器存档（不同格式 stencil，红鲱鱼，豁免扫描）
/opt/wheelhouse/                 # 离线轮子库（scipy 及依赖，构建期下载）
supervisor 服务：
  thermo-monitor                 # 每 30s 跑一遍标准流水线，THERMSTAT 行进 /var/log/thermo_sim.log
  trend-export（可选红鲱鱼）      # 趋势旁路导出，自带与判定无关的单位怪癖（对齐 kafka 红鲱鱼定位）
日志：/var/log/thermo_sim.log、/var/log/thermo-monitor.log（stderr 含 E2 的 WARN 回退行）、
      /var/log/trend_export.log、/app/ops/warnings.log（预警）
```

环境约束（复刻 431 题）：容器内离线（构建期网络下载 wheelhouse，agent 期不依赖外部网络）；
supervisord autorestart；组件为环境组成部分，`qc_crosscheck.py` 等模块不得删除或替换为桩
（P0 指纹检查）。

**CLI 契约**（题面写明，验题依赖）：`run_pipeline.py` 必须支持
`--config <yaml> --out-dir <dir> --stage all|materials|solve|post|qc|report --warnings-file <path>`，
使验题能用探针配置非破坏性重跑（431 题"验题可重复执行"的物理版前提）。

## 5. 验题契约草案（tests/test.sh 行为设计）

**判定总则**（复刻 431 题总则）：任一检查失败 reward=0；全部通过 reward=1；结果写
/logs/verifier/reward.txt；验题可重复执行（探针全部走 --config/--out-dir，不污染 /app）；
**物理正确性以行为探针判定**（输入可变、参照独立），源码/数据扫描仅作"修改真实发生"的
辅助证据（防伪造，泛化披露口径）。

**核心反作弊机制**：test.sh 内置**独立 numpy 参照解**（构建期与解析解标定后固化），
泛化探针使用 agent 未见过的材料参数/几何/边界值 → 任何"硬编码结果/桩"必然失败
（431 题注入链 nonce 探针的物理版）。

### 探针表

| 探针 | 判定 | 抓捕 |
|---|---|---|
| P0 环境在线 | python3+numpy 可用、wheelhouse 在位、supervisor 服务 alive、模块指纹（qc_crosscheck.py 存在且被入口调用） | 拆桩/删组件 |
| P1 端到端 | 标准场景 exit 0；summary.json 全字段；无 NaN；peak_T / t_threshold 对参照 ≤2% | 总体 |
| P2 泛化·未知参数 | ≥3 组探针场景：新材料参数（验题自带 materials 变体）/ 新几何（层厚）/ 新边界值，全部对内置参照 ≤2% | 硬编码/桩（最强防线） |
| P3 边界语义 | h 扫 3 档（500/2000/8000）+ T_inf 扫 2 档：峰值温度须单调响应且数值落点对参照 | F2 |
| P4 界面物理 | 双材质稳态：界面通量连续 + 与串联热阻解析解 ≤1%；R_c 场景另测 | F3、F5 |
| P5 收敛阶 | Δx 与 Δx/2 的 L2 误差比 ∈ [2.5, 5.5]（二阶格式） | F3 |

| P9 路径行为检查 | 流水线日志无 fallback WARN 残留；config 指向真实存在文件 | E2 |

| P12 报告硬断言 | 见 §6 diagnosis_report.md 断言 ①-⑦ | 报告 |

**扫描辅助（泛化披露，复刻 431 题双轨制）**：E3 固化错误数值的十进制形态不得以等值形态
残留于**生效数据文件**（.npz/.json/.csv，豁免 `legacy/`、备份后缀文件）；物理公式类错误
（换算倍率/差分系数）**不做字面扫描**（数值常数在物理代码中有大量合法出现场景，扫描不公平），
完全以 P2-P7 行为探针判定——契约如实披露该口径。

### 固定参数表（题面依据，复刻 431 题契约风格）

| 固定值 | 依据 |
|---|---|
| 材料（SI） | TIM: k=4.0, ρ=2800, cp=1150 → α≈1.24e-6；Cu: k=390, ρ=8960, cp=385 → α≈1.13e-4 |
| 几何 | TIM 0.30 mm（30 格，Δx=1e-5）/ Cu 1.5 mm（60 格，Δx=2.5e-5） |
| FTCS 稳定极限 | dt* = min_layers Δx²/(2α) = 1e-10/(2×1.24e-6) ≈ 4.0e-5 s（契约只披露公式口径，不披露数值——如同 431 题只披露"完整 header 行口径"） |
| 原故障 dt=5e-3 | ≈124×超限；naive 降 10×/100× 仍超限（惩罚拍脑袋）；题面复现场景 |
| P6 dt_probe=0.9dt* | 必须低于真实极限以验证"正确实现可通过"；t_end=2s → ~5.5 万步（numpy 秒级） |
| 收敛阶带 [2.5,5.5] | 理论值 4；带宽容纳非渐近区 |
| q 基准 1e5 W/m², h=4000, T_inf=45 °C, T_limit=110 °C | 稳态解析可手算（ΔT_tim=7.5K, ΔT_conv=25K），便于 agent 自检 |
| THRESH = T_inf + (T_limit−T_inf)×RATIO/100, RATIO∈[50,90] | 线性稳态 ⇒ 验题可在读出 RATIO 后精确构造 THRESH 场景 q 值（区间数学保证探针落在 (THRESH, T_limit)），对齐 431 题 THRESH+512 守卫推导 |
| THROTTLE_T_C 缺失/≤60 视为缺失 | 低于工况意义值属未有效声明 |

## 6. 产物契约（复刻 431 题四件套）

- `/app/ops/thermal_budget.env`：必含 `THROTTLE_T_C`（节流阈值，须与 config/summary 一致）
  与 `MARGIN_RATIO`（预警阈值百分比，[50,90]，缺失按 80）；
- `/app/ops/warnings.log`：告警行（自由文本，建议含时间与场景标识）；行为判定（P10）；
- `/app/ops/quality_gate.sh`：门禁（P11，截断/注入安全）；
- `/app/ops/diagnosis_report.md` 硬断言：① 含"归因"或"综合"；② 故障链以 → 呈现；
  ③ 数值对照：同时含换算倍率 `1000`、原 dt `5e-3` 与生效新 dt；④ 实质归因：含量化观测
  证据（`timescale`/`网格无关`/`convergence` 至少其一）+ "谁引入"（换算/校准/路径）与
  "哪层限制过小"（稳定极限/临界步长）两类表述；⑤ 含"余量"或"sizing"；⑥ 提及所修改项名
  （Robin/对流边界/调和平均/harmonic/stability/CFL 至少其一）；⑦ 含固化校准文件名 `fitted_2023`。
