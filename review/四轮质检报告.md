# 四轮质检报告（评分体系改造轮：加权 + 双级门槛 + 五层故障链）

- 题目 ID：humanlaya/coding-task（431 链路排查 · expert 定标：四维度改造）
- 质检日期：2026-11-17
- 改造依据（设计指引四条）：① edge 权重提升 + 6→10 项（kafka/mesh 计数维度）；
  ② 报告/门禁升为一票否决；③ 故障链 4→6 层（tracegate span 注入 + kafka 升级计分）；
  ④ 保持/补齐随机化（边界偏移、门禁注入标记与书写顺序、kafka 探针锚定）。

## 一、新评分架构

### 加权维度
| 维度 | 权重 | 子项数 | 内容 |
|------|------|--------|------|
| structure 结构完整性 | 0.1 | 5 | /app/ops 产物齐备 + LIM/WARN_RATIO 声明格式 |
| basic 基础修复 | 0.25 | 8 | 环境在线 / 端到端 / 注入链 / L1 / 扫描 / 声明一致 |
| edge 边界与防线 | **0.45**（原 0.3） | **10**（原 6） | 原 6 项 + **新增 07 span 精确计数、08 kafka 审计计数、09 双侧边界、10 预警内容实质** |
| quality 报告质量 | 0.2 | 8（原 7） | 原 ①~⑦ + **⑧ kafka 异步旁路三角说明** |

### 双级门槛（加权总分之上）
- **VETO → reward=0**：① 报告实质归因缺失（quality① 或 ④ 失败，含报告缺失）；
  ② 门禁核心行为失败（edge/02 干净误拦 或 edge/03、04 注入未拦截，含门禁缺失）
  → "只会改参数不会归因"的解法归零（远低于 0.4）。
- **CAP → reward=min(score, 0.45)**：注入链完整性（basic/03）、span 精确计数（edge/07）、
  kafka 审计计数（edge/08）任一失败 → "改对一半"（漏 span 规格恢复 / kafka 治理 /
  绕层）的解法封顶 0.45，不可能越过 0.5。

### 故障链 4→6 层（"改对一半"扣分面扩大）
| 层 | 故障 | 判定 |
|----|------|------|
| L1 nginx | 16k < 完整行 16402B | 行为+扫描（原） |
| L2 tracegate | max_header_bytes 10240 | 扫描（原） |
| L3 meshd | yaml 12288 + **supervisor env 运行时覆盖**（三轮） | 行为+扫描（原） |
| L4 backend | 移码 8192 + go:embed 固化 + legacy 残留 | 扫描+重编译（原） |
| **L5（新）** | tracegate `span_bytes` 768→**384**（GW-1211 带宽专项下调） | edge/07 计数锚定 **769/1537/512 精确值**（缩水与虚增都判失真）+ span_bytes 384 残留扫描 + basic/03 注入链增幅（384 时增幅 ≈1922<2048 连锁失败） |
| **L6（新计分）** | kafka `message.max.bytes` **16384**（原噪声，升级计分） | edge/08：大探针（锚定 min(LIM−256, 32768)，随机化）审计事件 45s 内落盘 + server.properties 16384 残留扫描 + 报告断言⑧ |

### 随机化（"猜"的解法拿不到分）
- edge/01 上边界偏移随机 {2048,4096,8192}；edge/09 双侧偏移独立随机 {512,1024,1536}；
- edge/03/04 门禁注入标记（路径/字节数/IP/msec）随机化 + **edge/04 两日志写入顺序洗牌**
  ——门禁须按"431 证据"语义逐源拦截，不能匹配固定样本/顺序；
- edge/08 kafka 探针按声明 LIM 自适应锚定；edge/10 预警探针偏移随机 {512,768,1024}。
