### 一轮发现的问题（本轮已全部修复）
1. **[设计级] 原方案的"陈旧部署"陷阱挂在运行时读取的配置文件上不成立**（进程重启即读到磁盘新值）→ 改为 `//go:embed` 编译期固化配额（T3a 实测：磁盘 65536、运行 8192）。
2. **[击穿参考解] test.sh 第 6 节③要求报告含字面 8192**，而新故障链下 solve.sh 报告的"修改前"取值全为磁盘健康值 → 报告模板补"原故障值口径"静态叙述（含 8192）。
3. **[文档-实现不一致（既有）] instruction.md 声称扫描 `(^|[^0-9])8192([^0-9]|$)`，test.sh 实现是关键词锚定** → 统一为两者并存：十进制全量（覆盖退役入口常量）+ 关键词锚定的移码/十六进制变体，文档同步。
4. **[致命兼容] solve.sh `find_app_pid` 按上游端口找进程**——链路多组件化后首个 proxy_pass 是 tracegate:9100，会把后端二进制覆盖到 tracegate 上 → 改为校验 exe 属于后端模块目录，否则回退 cmdline 匹配（pgrep 路径实测通过）。
5. **[顺序不确定] 4.2 MaxHeaderBytes 循环带 break** + legacy 文件若含同名键会被漏改/误改 → 去 break + WIRE_FILE 按 `http.Server{` 识别；legacy 放 root 包且不含相关字样。
6. **[报告准确性] 4.3 多配置文件遍历时 QUOTA_BEFORE 被诱饵文件覆盖** → 逐文件记录修改前值并累计报告行。
7. **[公平性] 变体扫描细节若未披露，按移码书写修复值的 agent 会被暗坑判 0** → 契约泛化披露扫描口径（不点名具体形态）。
8. **[测试工装] 本机 grep 是 Claude Code 注入的 ugrep 函数**（容器为 GNU grep）→ 脚本方式执行验题用 GNU grep，等价性确认；pkill 改 `-x` 精确匹配避免误杀调用方 shell。

### 已知局限（披露，不阻塞）
- **完全伪造型作弊的残余风险**：删除后端源码 + 桩二进制（伪造响应体/回显头）+ 独立日志观察器产 warnings，理论上可通过当前全部检查。防线依赖契约已披露的"源码/配置扫描"辅助证据与行为探针组合；该暴露为原题继承（原验题同样存在），本轮通过 T3c 证实"天真桩"必被预警防线抓住，完全伪造型留待评测期监控。
